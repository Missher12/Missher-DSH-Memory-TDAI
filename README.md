# DSH Memory TDAI · 全局记忆

基于 [TencentDB Agent Memory](https://github.com/TencentCloud/TencentDB-Agent-Memory) 思路二次开发的 DeepSeek Harness 记忆插件。采用 MIT 许可证，非腾讯官方产品，无腾讯背书。

[桌面与插件总入口](https://github.com/Missher12/Missher-DeepseekHarness-Desktop) · [下载与版本记录](https://github.com/Missher12/Missher-DSH-Memory-TDAI/releases) · [技术参考](docs/technical-reference.md) · [验证记录](verification/2026-10-30-0.1.2-local.18-acceptance.md)

## 它能帮你做什么

换一个会话后，仍能检索同一 DSH profile 中已经保存、允许使用的事实与偏好。项目和会话用来说明记忆来自哪里；普通使用入口统一查看全局记忆，不需要手动切换项目范围。不同 profile 的数据保持隔离。

插件先保留来源，再提炼事实，按需检索相关片段。它不是把所有历史原文塞进每次请求，也不是无限扩充模型上下文。搜索与界面统计只读取本地数据；自动提炼可能调用你配置的宿主模型并产生费用。

采集只接受真实用户消息、用户问答回复和模型对话。其他插件注入、压缩摘要、模型切换和宿主内部通知不作为用户原话落盘、提炼或发起事实查询。旧库中这类来源的正文保留，相关记录按当前来源规则排除，不让历史注入继续支撑事实或偏好。

## 四层记忆如何工作

| 层级 | 保存什么 | 用途 |
| --- | --- | --- |
| L0 原始对话 | 可追溯的对话来源 | 查看原始证据，帮助后续提炼 |
| L1 提炼记忆 | 从来源中提取的事实与偏好 | 搜索、查看详情，并遗忘不再需要的内容 |
| L2 场景索引 | 对相关记忆的组织与关联 | 更容易找到某类任务或场景的线索 |
| L3 画像 | 基于可读取来源形成的摘要 | 在有证据的基础上组织长期偏好 |

高置信度、有来源且无显式冲突的自动提炼结果可以投入使用；不确定或冲突内容保留候选状态。遗忘会使相关记忆及派生引用失效，重试不应把它重新复活。

## 能记住多少、能省多少 Token

插件不设每日 Token／任务次数配额，也不设累计记忆条数配额。旧配置中的每日配额（包括 0）不再阻断提炼或画像请求。实际容量仍取决于本地磁盘与基础设施，不承诺物理容量无限。

召回不会因为超过 250ms 而整包丢弃；仍按相关性选择内容，保留单次分页、候选和上下文大小控制，部分结果会明确标注。身份、来源权限、当前修订和最终发布证明仍须通过。默认 `retention.days=0` 不自动清理 L0；用户明确设置的保留期、删除和遗忘仍生效。

全局召回和全局搜索使用同一组有界问题词，优先采用有意义的词，避免单字虚词、重复词和末尾执行限制挤占相关事实的预算。提炼提示明确排除只约束当前回答的格式和工具指令，长期偏好与项目待办仍可保留。

提炼与画像保留单活动请求防重、真实用量记录和未知调用保护，不会因取消配额自动重试未知请求。显式关闭生成、使用、采集或提炼的设置仍有效。账户额度和提供方限制由相应服务控制。没有统一的 Token 节省百分比，效果取决于检索相关性和模型能力。

节省输入的方式是只检索、注入有用的短片段，避免重复携带全部历史。提炼本身也会花费模型 Token，因此应比较“提炼成本 + 召回输入成本”和原来的历史输入成本，再判断实际收益。

页面会自动读完有边界的本地扫描，合并成统一计数和普通列表分页，不再需要“继续读取下一批”。扫描期间只显示进度；数据中途变化会重新读取，避免把不同版本相加。`≥` 仍表示因不可读来源等原因只能确认的下界，部分结果不冒充精确总数。年度活动图统计记忆首次修订及后续内容／证据修订，不把每次打开页面或召回都算成新增记忆。超出单次页面资源范围时会提示缩小搜索条件。

场景和画像按小批完整核验来源，超过 100 条也不会因数量被略过。大场景和项目画像跨工作窗口保留原只读连接及版本校验，只保存当前 15 条成员和汇总证明；全局画像继续核验后续项目。每次调用和每个工作窗口仍有预算，界面自动继续读取。来源中途修改、撤销或过期会使本次结果失效，不能发布旧正文。

场景生成只接受真实对话来源；写入连接首次升级时会重建旧派生索引，避免历史插件注入文本污染整个场景，保留 L0/L1 正文。活动日历也按记忆分组流式去重，不再因为累计 ID 空间用满而把首页标记成部分结果。L0 遵循采集设置，L1 保留来源及批准状态，L2 组织完整场景成员，L3 是有来源的画像摘要，不要求把每条对话复制到四层。

首页显示提炼排队、历史失败、历史结果未知和待确认数量；历史异常附带发生时间，以普通记录展示，不冒充当前运行故障，也不把失败伪装成已完成。待确认的候选可在长期记忆中查看，核对来源后确认启用或遗忘，确认前不参与召回。后台提炼会按宿主实际公布的模型能力选择较低思考强度，默认输出上限为 4096 Token；用户显式设置的上限仍有效。后台提炼可独立指定模型，不改变对话模型；设置页显示当前提炼模型。高级调用方可通过 `memoryTdai/updateSettingsAck` 同时设置 `extractionProvider` 和 `extractionModel`，两项同时设为空字符串时恢复跟随会话；设置会持久化并回读确认。历史已计费或结果未知任务不会自动重发。

## 角色底色与沟通风格

插件可选提供一段稳定的角色底色（默认关闭，在设置页启用，可用自己的描述覆盖，留空使用建议默认）。角色底色只影响表达方式，不声明身份或能力，也不是新指令；它是独立配置，与 L3 用户画像分开保存、互不覆盖。

沟通风格从同一 profile 的项目中有真实用户来源的已批准 preference 学习，不再只检查最早八个项目。保守识别明确表达的回答长度、直接程度、正式程度、幽默、语言和先给结论偏好，投影为固定的表达标签；没有明确表述或无法识别的内容不会猜测补全，历史原文不会直接变成行为指令。引用携带来源项目与修订，遗忘、撤销和当前可读性规则继续生效；修订后按当前证据重新计算。

在 Memory 首页齿轮中启用“稳定角色底色”，可编辑角色描述并保存。浏览和召回不会增加模型调用；有已学沟通偏好时，为角色与偏好预留不超过总注入预算一半的空间，同一来源共用引用，余下空间用于事实，最终指引重新核验当前来源。没有已学偏好时保留原有事实优先策略。L3 用户画像在没有词面事实命中时仍可按配置提供，超出预算的画像会省略。

## 两个独立开关

在 DSH **设置 → Memory** 中点击齿轮：

- **自动生成记忆**：控制新的采集与提炼。关闭后保留已有记录，但停止新生成，并阻止在途旧结果重新生效。
- **在对话中使用记忆**：控制后续对话的记忆注入和读取工具。关闭后仍可以在设置页查看已有记录。

开关独立保存，失败会显示明确状态；重试提交原来失败的设置，并回读确认。支持浅色／深色主题、搜索、详情、来源、四层浏览和年度活动图。

当前源码版本为 `0.1.2-local.18`，面向 DSH `0.2.1-rc.4`。本次修复工具调用回复没有文字时的模型路由绑定、截断结果的失败分类、删除来源后的任务退休，以及有明确授权的历史任务恢复。提炼时使用批内短来源编号，保存前严格映射回原始来源，避免模型抄错长 ID；未知编号仍会拒绝。恢复会创建独立任务并关联原任务，保留原调用和用量证据；重复提交同一恢复请求不会再发一次调用。真正结果未知的请求仍需核实，不能假定未计费。

## 从源码构建

需要满足 `package.json` 声明的 Node.js 与依赖版本。

```sh
git clone https://github.com/Missher12/Missher-DSH-Memory-TDAI.git
cd Missher-DSH-Memory-TDAI
npm ci
npm run build
npm pack
```

通过 DSH 的插件管理器安装生成的 bundle（`install_bundle`）。不要直接改日常 profile 的 `package.json` 或 `cordis.patch.yml`。本仓库的 `private: true` 用于避免误发 npm，不影响 GitHub 源码的公开与 MIT 授权。

开发者需要检查时可运行 `npm run typecheck` 和 `npm test`；这些命令会消耗本机资源。针对原生 Host Loader 的测试需提供实际宿主模块；缺少宿主模块不能按通过计算。

## 数据与边界

有宿主 profile 时，默认数据目录为该 profile 目录下的 `memory-tdai/`；同一 profile 内跨项目、跨会话共享，不同 profile 默认独立。无 profile 服务的最小宿主沿用 `$DSH_HOME/memory-tdai/`。旧版本共用的目录只允许升级时明确记录归属的 profile 继续使用，未归属的旧数据保留，不由新 profile 自动接管；显式 `dataDir` 仍按用户指定路径使用。项目分片保留来源信息，没有在此版本中承诺跨设备自动同步。

- 历史记忆是参考数据，不是新的操作授权或系统指令。
- 浏览页面和检索统计不应额外调用模型；自动生成按配置使用宿主模型。
- 卸载插件不等于删除记忆数据。迁移设备前请单独备份 profile 数据。
- 向量后端、真实商业模型效果和各操作系统的当前安装效果，应以相应验证记录为准。
